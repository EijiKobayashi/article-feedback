# AIエージェント用プロンプト

## 使い方

下のテンプレートをそのままエージェントへ渡し、`依頼内容` と `受け入れ条件` だけを書き換えてください。エージェントが変わっても、同じ資料・同じ順序・同じ完了条件で進められます。

## 実装依頼テンプレート

```text
あなたは Article Feedback の開発担当です。

最初に、リポジトリ直下の AGENTS.md を読み、そこから参照される README.md と docs/*.md をすべて確認してください。書かれていない仕様を推測で増やさないでください。

【依頼内容】
ここに変更したい内容を書く。

【受け入れ条件】
- 条件1
- 条件2
- 条件3

【必須方針】
- 開発中のため、後方互換とデータ移行は考慮しない。
- 現時点で最も単純で理想的な設計を採用する。
- KISSを守り、将来用の抽象化・互換レイヤー・未使用設定を追加しない。
- WordPress標準APIとブラウザ標準APIを優先する。
- セキュリティ確認を省略しない。

【作業順序】
1. 資料を先に更新する。
   - 要件: docs/requirements.md
   - DB: docs/data-model.md
   - HTTP入出力: docs/api-specification.md
   - 利用方法: README.md
   - 更新後、資料間の矛盾がないか確認する。
2. 受け入れ条件を表す失敗テストを先に書き、失敗を確認する。
3. テストを通す最小限の実装を行う。
4. 全テストと構文確認を実行する。
5. 不要コード、重複、古いコメント、資料との矛盾を削除する。

【回答に必ず含める内容】
- 変更した資料
- 追加・変更したテストと、実装前にどう失敗したか
- 最小実装の概要
- 実行した検証と結果
- 残課題（なければ「なし」）

質問がなくても安全に進められる場合は、既存資料を正として作業を完了してください。要件を大きく変える不明点だけ、実装前に質問してください。
```

## バグ修正テンプレート

```text
AGENTS.md と関連資料を読んでから、次の不具合をTDDで修正してください。

【不具合】
再現手順、期待結果、実際の結果を書く。

最初に「期待結果」を要件・API・データモデルへ反映し、再現する失敗テストを書いてください。その後、原因に最も近い箇所だけを最小修正してください。後方互換、データ移行、将来用の抽象化は不要です。最後に全テスト、PHP構文、資料との一致、不要コードの有無を確認してください。
```

## レビューテンプレート

```text
AGENTS.md、README.md、docs/*.md を正として変更をレビューしてください。

優先順は次のとおりです。
1. 要件違反・データ破損・セキュリティ問題
2. テスト不足
3. 資料と実装の矛盾
4. KISS違反、重複、不要な互換処理・抽象化

指摘には、対象ファイルと行、発生条件、影響、最小の修正方針を含めてください。問題がなければ、その旨と残る検証範囲を明記してください。
```
